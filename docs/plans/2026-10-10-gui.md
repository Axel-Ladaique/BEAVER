# GUI navigateur — implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Checkbox steps.

**Goal :** `aerorib gui` ouvre une page locale qui permet d'importer une aile, régler les paramètres avec un aperçu instantané (coupe, vue de dessus, chiffres, 3D approximative), lancer la génération complète avec progression, comparer l'historique des essais, ouvrir le résultat dans Bambu, et éditer les profils matière.

**Spec :** `docs/specs/2026-10-10-gui-design.md` (à lire en entier) ; cœur : `docs/specs/2026-10-09-aerorib-design.md`, `docs/specs/2026-10-10-p1-addendum.md`.

## Global Constraints
- Le serveur écoute **127.0.0.1 uniquement**, port libre ; un **jeton** aléatoire par lancement est exigé sur toutes les routes `/api/*` (en-tête `X-AeroRib-Token` ou paramètre `token`) ; la page reçoit le jeton via l'URL ouverte.
- **Aucune géométrie nouvelle dans la GUI** : elle appelle le cœur (`aerorib.*`). Le calcul d'aperçu vit dans `aerorib.preview` (pur Python, testable sans serveur).
- Messages et interface **en français**. Unités mm.
- Windows + macOS. Travaux en processus séparé : fonctions de module uniquement (spawn).
- Chemins confinés à la racine des projets ; noms assainis ; import STEP ≤ 200 Mo.
- Frontend sans étape de build : `src/aerorib/gui/static/` (HTML, CSS, modules JS) ; three.js depuis `https://cdn.jsdelivr.net/npm/three@0.160.0/` (version figée, import map).
- Tests : `fastapi.testclient.TestClient` pour l'API ; les longs calculs sur l'aile synthétique `wing_x_bodies()` ; marquer `slow` > 20 s.
- Ne jamais affaiblir un test. Commits français + trailer.

### Task 1 : Serveur, jeton, commande `gui`, raccourcis
- Dépendances `fastapi`, `uvicorn`, `python-multipart` (uv add).
- `create_app(root: Path, token: str) -> FastAPI` : sert `static/` à `/`, `GET /api/sante` → `{"ok": true, "version": …}` ; middleware : toute route `/api/*` sans jeton valide → 401 `{"erreur": "jeton manquant ou invalide"}`.
- `run_gui(root, port=0, open_browser=True)` : choisit un port libre, génère un jeton (`secrets.token_urlsafe`), lance uvicorn sur 127.0.0.1, ouvre `http://127.0.0.1:<port>/?token=<jeton>` (module `webbrowser`), affiche l'URL dans le terminal.
- CLI : `aerorib gui [--dossier DIR] [--port N] [--sans-navigateur]` ; défaut `DIR = ./projets`.
- Raccourcis : `lancer-aerorib.command` (macOS, `cd "$(dirname "$0")" && uv run aerorib gui`, exécutable) et `lancer-aerorib.bat` (Windows, `cd /d %~dp0` puis `uv run aerorib gui`, `pause` en cas d'erreur).
- `index.html` minimal (titre « AeroRib », onglets vides) pour vérifier le service statique.
- Tests : santé avec/sans jeton (200/401), `/` sert l'HTML, l'hôte d'écoute est 127.0.0.1 (tester la fonction qui construit la config uvicorn), la commande `gui --help` existe.
- Commit `feat(gui): serveur local, jeton et commande gui`.

### Task 2 : Projets (stockage, import, inspection, config)
- `ProjectStore(root)` : `list() -> [ {nom, cree, nb_essais} ]`, `create(nom, step_bytes, filename) -> Projet` (assainit le nom, refuse les doublons, copie en `piece.step`, `config.yaml` initial = `{}` ou `material: pla_aero`), `get(nom)`, `inspect(nom)` → corps/rôles/notes/diamètre longeron (via `read_step`/`classify`), `read_config(nom)` (YAML brut du projet), `write_config(nom, data)` → valide avec `load_config(path)` (ConfigError → 422 avec message français, rien écrit), `effective_config(nom)` → config fusionnée (défauts + profil + projet) avec **provenance** de chaque valeur (`défaut` / `profil` / `projet`).
- API : `GET /api/projets`, `POST /api/projets` (multipart : nom + fichier STEP), `GET /api/projets/{nom}`, `GET /api/projets/{nom}/corps`, `GET/PUT /api/projets/{nom}/config`, `GET /api/projets/{nom}/config/effective`, `GET /api/schema` (JSON schema de `Config` + liste des matières/profils), `DELETE` non fourni.
- Tests : création avec le STEP synthétique écrit par `write_step(wing_x_bodies())`, nom avec `../` refusé, doublon refusé, fichier trop gros refusé (413), inspection = 1 peau + 1 longeron, config invalide → 422 avec message français et fichier inchangé, provenance correcte pour une valeur venant du profil et une du projet.
- Commit `feat(gui): projets, import STEP et configuration`.

### Task 3 : Moteur d'aperçu (`aerorib.preview`)
Fonctions (spec « Aperçu : calcul ») :
- `prepare(step_path, cfg) -> Prepared` (orientation, peau orientée, `MidSurface`, trous avec rebouchage/attache selon cfg, boîte englobante) ; cache LRU en mémoire par (empreinte SHA-1 du fichier, champs de cfg qui l'influencent).
- `plates_2d(prep, cfg) -> list[Plate2D]` (couche, famille, c, d0, d1, polygones (s, y), profondeur) — réutilise `features.ribs` (exposer une fonction qui renvoie les profils 2D sans construire les solides si nécessaire, sans changer le comportement de `diamond_plates`).
- `section(prep, plates, cfg, z) -> SectionView` : polygones de la couche approximée, liste des défauts (`connectivity`, `material_width`, `narrow_slit`) avec bornes, bande centrale (polyligne), trous.
- `planform(prep, plates) -> list[segments (x0, z0, x1, z1, couche)]` + rectangle de l'aile + coupes de tronçons.
- `estimates(prep, plates, cfg) -> dict` : `plaques` par couche, `troncons` (hauteurs), `trajet_m`, `masse_g` (sur 20 couches échantillonnées, extrapolé), `duree_s` (= plaques × `SECONDS_PER_PLATE` = 1.5 + préparation).
- `plates_mesh(prep, plates) -> bytes` (STL binaire des plaques solides, via `plate_solid` + `to_mesh` ; limiter à 600 plaques avec message sinon) et `skin_mesh(prep) -> bytes`.
- Tests (aile synthétique, `segment.max_height: 30`) : `section` à mi-hauteur a ≥ 1 encoche par plaque qui coupe z et la même topologie (nombre de polygones, absence de trous) que la vraie couche obtenue par `generate_skin` + `slice_layers` à la même hauteur (comparaison d'aires à 5 % près) ; `planform` renvoie des segments à ±angle ; `estimates.plaques` = nombre de plaques réellement générées par `generate_skin` ; `trajet_m` à 10 % du trajet du rapport de `validate` ; `prepare` est mis en cache (deuxième appel < 50 ms) ; `plates_mesh` relu par trimesh est non vide.
- Commit `feat(preview): aperçu rapide sans booléens`.

### Task 4 : API d'aperçu
- `POST /api/projets/{nom}/apercu` corps `{config: <dict projet modifié non enregistré>, z: float|null}` → `{section, planform, estimates, avertissements}` (la config proposée est validée ; erreurs 422 françaises). `GET /api/projets/{nom}/apercu/plaques.stl?…` et `/peau.stl` pour la 3D (config passée en paramètre encodé ou dernière config d'aperçu mémorisée).
- Préparation lente (première fois) : la réponse indique `"preparation": true` avec une progression simple ; les appels suivants sont rapides.
- Tests : réponse complète sur l'aile synthétique, 422 sur config invalide, deuxième appel avec seul `z` changé < 1 s, STL servis.
- Commit `feat(gui): API d'aperçu`.

### Task 5 : Générations (travaux + historique)
- `JobManager(store)` : `start(nom) -> id` (refuse si un travail tourne : 409), lance un processus (fonction de module `_run_job(step, config_path, out_dir, queue)`) qui exécute `run_model` + `export_results(... formats step, stl, 3mf ...)` et pousse les messages de progression ; `status(id)`, `cancel(id)` (termine le processus, essai marqué « annulé »), `events(id)` (générateur pour SSE).
- Chaque essai : dossier `essais/<horodatage>/` avec `config.yaml` résolu, `resume.json` (statut `ok`/`non imprimable`/`erreur`/`annulé`, durée, nervures, tronçons, masse, trajet, erreurs et avertissements, fichiers), sorties, rapport.
- API : `POST /api/projets/{nom}/generations`, `GET /api/generations/{id}` (statut), `GET /api/generations/{id}/flux` (SSE), `POST /api/generations/{id}/annuler`, `GET /api/projets/{nom}/essais`, `GET /api/projets/{nom}/essais/{essai}` (+ fichiers via `/fichiers/{chemin}` confiné), `GET /api/projets/{nom}/essais/diff?a=…&b=…` (différences de config à plat), `POST /api/projets/{nom}/essais/{essai}/ouvrir-bambu` (appelle `open_in_bambu`, monkeypatché en test), `POST …/ouvrir-dossier`.
- Tests (aile synthétique rapide) : génération complète → `resume.json` ok et fichiers présents ; deuxième lancement simultané → 409 ; annulation d'un travail long (monkeypatch d'une étape lente) → statut annulé ; flux SSE contient des messages de progression puis un message final ; diff entre deux essais aux réglages différents ; chemins hors dossier refusés.
- Commit `feat(gui): générations en arrière-plan et historique`.

### Task 6 : API des profils
- `GET /api/profils` (nom, origine, gabarit, existe), `GET /api/profils/{nom}` (valeurs fusionnées + provenance embarqué/utilisateur), `PUT /api/profils/{nom}` (écrit dans `./profiles/<nom>.yaml` **seulement les valeurs différentes de l'embarqué**, valide la config résultante → 422 française sans écrire), `POST /api/profils/{nom}/copier` (comme la CLI). Le dossier des profils utilisateur = `./profiles` du répertoire de lancement (ou `AERORIB_PROFILES`).
- Tests : édition d'une valeur → fichier ne contient que cette valeur ; valeur invalide → 422 et fichier inchangé ; profil sans embarqué (nouveau nom) ; asa_aero sans gabarit signalé.
- Commit `feat(gui): API des profils matière`.

### Task 7 : Interface (frontend)
Une page à onglets (Projets, Réglages, Aperçu, Générer, Historique, Profils), design sobre lisible clair/sombre, responsive à partir de 1024 px.
- **Projets** : liste + bouton « Nouveau projet » (nom + sélection STEP), carte des corps/rôles après import.
- **Réglages** : formulaire généré depuis `/api/schema` + `/config/effective` (provenance : valeur héritée en gris avec étiquette « profil »/« défaut », bouton « surcharger » / « revenir à l'hérité ») ; couches de nervures en liste (ajouter/supprimer une couche) ; validation via l'API à chaque modification (débounce 400 ms), message d'erreur sous le champ concerné ; bouton « Enregistrer ».
- **Aperçu** (à côté des réglages sur grand écran) : SVG de la coupe avec curseur de hauteur (défauts entourés en rouge, bande centrale en pointillé), SVG de la vue de dessus (deux couleurs pour les deux réseaux, tronçons en tirets), chiffres estimés, vue 3D three.js (peau translucide + plaques, orbite) chargée à la demande.
- **Générer** : bouton, barre/journal de progression (SSE), annuler, résumé final, liens rapport / STL / 3MF, « Ouvrir dans Bambu ».
- **Historique** : tableau des essais, sélection de deux → diff, actions par essai.
- **Profils** : liste + formulaire d'édition (mêmes composants que Réglages), enregistrer, copier.
- Le jeton est lu dans l'URL et envoyé sur chaque requête ; perte de connexion → bandeau « serveur arrêté ».
- Tests : un test API qui vérifie que `index.html` référence les modules et que tous les fichiers statiques référencés existent ; contrôle visuel fait par le contrôleur dans le navigateur intégré (captures).
- Commit(s) `feat(gui): interface …`.
